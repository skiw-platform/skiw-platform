- `app/accounts/auth/login.py` (new): `login(request, user, *, factor)` (owner Q7 (a), no `django.contrib.auth`). In order:

  3. `cycle_key()`;

### Findings

### [P3] #1 — With DEBUG on, the root handler prints exception messages, from a cached traceback
- **Category:** privacy (log content), UNI-09
- **Evidence:**
  - Django's default `django` logger keeps its `console` handler (`require_debug_true`), and the
    `django` logger propagates to root.
  - With DEBUG on, `console` formats the record first, using the stock `Formatter`. That stores the
    full traceback text in `record.exc_text`.
  - `logging.Formatter.format` reuses a cached `exc_text` and never calls `formatException`. So the
    root `stderr` handler prints the cached text, messages included (probe above).
  - `.env.example:4` sets `DJANGO_DEBUG=1`, so this is the local default. No host sets `DJANGO_DEBUG`
    (`grep` of `infra/`), and `docker-compose.yml:29` defaults to `0`. That is why this is P3.
- **Failure scenario:**
  - Locally, a `django.*` logger other than `security` or `request` logs an exception whose message
    holds row data, for example a template or DB error.
  - The email then shows in the dev terminal, twice.
  - A later handler that formats before `stderr` would do the same on hosts.
- **Required correction:**
  - Make `NoExceptionText` ignore the cache. For example, in `format()`: save `record.exc_text`, set it
    to `None`, call `super().format(record)`, then restore the saved value.
  - Add a test with `DJANGO_DEBUG=1` and a `django.*` (non-`request`) logger.
- **Owner:** builder · **Disposition:** deferred to M3d-2b (the next PR) · **Status:** open (deferred)

### [P3] #2 — The Semgrep rule misses a bound-method alias
- **Category:** test gap (guard rule)
- **Evidence:**
  - The patterns match `$SESSION.start_new_lifetime(...)` and `getattr($SESSION, "…")`.
  - `fn = request.session.start_new_lifetime` followed by `fn()` passes unflagged (probe above).
  - The fixture lists `getattr` as "the evasion under test", so evasions are meant to be in scope.
- **Failure scenario:** a later "refresh session" helper keeps the method in a variable or passes it
  as a callback. It renews the absolute deadline without a login, and lint stays green. The session
  could then outlive `SKIW_SESSION_ABSOLUTE_H`, which is what spec D6 rules out.
- **Required correction:**
  - Match the attribute itself, which also covers calls: `$SESSION.start_new_lifetime` and
    `$SESSION.astart_new_lifetime`.
  - Add an alias case (`# ruleid:`) to the fixture.
- **Owner:** builder · **Disposition:** deferred to M3d-2b (the next PR) · **Status:** open (deferred)
