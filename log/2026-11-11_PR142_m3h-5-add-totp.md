### Residual risks and test gaps
- **The marker window (M3d, unchanged).** Suppose a password step or a second factor finishes while a change transaction is open: after it began, before it committed. That login stamps a time later than the marker's transaction start, so it survives. The window is the change transaction, including any wait on `hold`'s lock. Argon2 runs outside it, so it is short. Closing it would mean the sign-in check taking the user-row lock (`FOR UPDATE`) and re-checking `changed_since`. That is not required here; it is worth a line in M3h-6's design if the owner wants it closed.
- **No notice to the user when an authenticator is added.** An attacker with a live session and a fresh step-up could add their own TOTP for persistence. They would need a real TOTP code at step-up, every other session would end, and the factor appears in the list. Audit events and owner alerts are M5 and Q4 (a), so this is not a finding here.
- **Not run by me:** `host-test`, `host-test-live`, `secrets-test`, `e2e`, `audit`. CI `host`, `security` and `image` are green on this head.
