### Findings

### [P3] The import rule can be sidestepped by reading the key from settings
- **Evidence:** `tenancy.token` is ~10 lines of `hmac` over `settings.SKIW_TENANT_TOKEN_KEYS()`
  (`config/settings.py:70`), and nothing limits who reads that setting. A module that may not import `mint` can
  call the setting and `hmac.new` directly. Today only `tenancy.keys` reads it.
- **Impact:** hygiene only. The spec makes the MAC the boundary against injected SQL, not against app code,
  which holds the key in-process anyway. But the rule's message ("any module holding mint() could make a
  token") is only half-enforced without this.
- **Correction (M4c-4b-2, where `with_agency()` starts reading the key):** add a pattern that limits
  `settings.SKIW_TENANT_TOKEN_KEYS` (and `getattr(settings, "SKIW_TENANT_TOKEN_KEYS")`) to `config/settings.py`,
  `tenancy/keys.py`, the two binding modules and tests, with fixture lines and a pinned exclude list. Optionally
  add `importlib.import_module(".token", ...)` to the import rule.
