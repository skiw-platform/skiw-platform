## 1. Goal
M4-core (PRs 83–167) gave the tenant boundary: `guard`, `with_agency()`, `async_with_agency()`, the policy template, the schema check and the TEN-08 harness. Two things the main spec puts in M4 (§9 M4 row) are still missing, and both block real work. **(1) Who may do what inside an agency.** Today the AUTH-01 wrapper lets any active user with a second factor past its role step (`app/accounts/auth/wrapper.py:161`; plan M3 §9 item 6), because there is no role data, `user_role`, `org_unit` or `scoped()`; AUTH-03 is n/a. Per the owner direction of 2026-11-21 (OD-1, a proposal until M4r-0), who may do what is agency data an admin edits, within a fixed catalogue of permissions and fixed safety rules. Before any client data exists (M7, M8), every action must be checked against the agency's stored permissions and every client-data read must go through `scoped()` (D18). **(2) Jobs bound to a tenant.** `jobs.enqueue_in_tx` is the M0c subset (`app/jobs/enqueue.py:15-35` [V]): no derived agency, no RLS id check, no `args_mac`, and the worker neither verifies a MAC nor enters `with_agency()`. `runworker` still hands over to `manage.py procrastinate worker` (`app/jobs/management/commands/runworker.py:27` [V]), the connector swap D5 forbids, so handler-side enqueue and the periodic fan-out cannot work. No business task can be registered until this lands. The reader is Ying (owner) and the Reviewer; the users are the ~5 SK iWealth staff.

## 2. Non-goals
- `with_admin_operation` / `ADMIN_TX_HELPER`: TEN-12 needs `audit_event` (M5). No cross-agency or global write path is added.
- `guard.approval_mac_key` and `guard.approval_mac_ok` (M9).
- The operator release of a stalled job (M5, needs `audit_event`); the admin dead-letter screen (M9). M4-rest ships the read-only report and the `failed`-job retry only.
- Any business task, sweeper or periodic schedule. Only test-only probe tasks are registered (D5 "Staging").
- Client, plan, outbox or Drive tables. `scoped()` is proven on a test-only probe model; each later table plugs into it (§9 done-when).
- **Every admin screen** (staff list, roles, the permission tick grid, assignments, org units, disable user) and the owner-performed factor reset: moved to M5 per Q3 (owner-selected per builder session 2026-11-21, unverified here; Decision 24, §10.1), still a must-have before any real client data. M4-rest is the data model, the evaluation and the operator commands only; no in-app route changes a role, a permission tick, an assignment, an org unit or a factor in M4-rest. What the M5 screens must cover is listed in Decision 29 "M5 must"; they are not designed here.
- An "assigned clients" scope: the catalogue scopes are `own`, `team`, `agency` only (Decision 4). A scope that needs a client-assignment model is a catalogue addition by spec revision in the milestone that creates `client` (Decision 5).
- The owner/admin passkey test named in M3 plan Q9 (a): spec v1.22 removed that rule; its replacement ("no second factor → no access") already runs in M3 (M3f-3b-1, M3f-3c-2; plan M3 Q9 amendment). Nothing is deferred here for it.
- Signed periodic parents (second-agency gate, §4.2 item (b)); the second agency stays locked, and seeding starting roles for a second agency is part of that gate (Decision 5).
- `async_with_agency()` (done, M4c-8, DECISIONS 2026-11-20).

## 5. Flows
**5.1 A signed-in request (Decisions 7, 26).** Session → `with_agency(session agency)` (idle, revoked, active) → factor present → `user_role ⨝ role_permission` rows for this user and `permission` → grants whose line matches the route's `line` → none: 403 `forbidden` (signed in) → drop S grants (catalogue `(code, scope)`) without a fresh `recent()` for their purpose → none left: 403 `stepup-required` → schema → handler with `Signed.access` (kept grants only). Failure of any step stops; only step 2 logs out (unchanged).

**5.2 A scoped read.** Handler calls `scoped(Model, signed.access)`; the CTE for `team` grants runs once per request; the result is a QuerySet the handler may narrow further but never widen (no `_unscoped`).

**5.3 Assignment (operator, Decisions 12, 27–32).** `accounts_role assign <email> <role> --unit <id> --line <line> --operator <code>` → operator code checked against `SKIW_OPERATOR_CODES` (bad → exit 1, nothing opened) → `with_agency(deployment agency)` → roles lock → `set_config('skiw.operator', <code>, true)` → user by email, role by name, org unit, all under RLS (unknown → exit 1, no other account named) → INSERT `user_role`; inside that statement the lock trigger re-takes the lock and `user_role_audit` inserts the `role.assigned` row (ids from `NEW`, line, operator code, `at` = database time, `agency_id` = the row's) → commit (deferred checks). Any failure up to and including the commit rolls back the change and the event together; a refused change writes no event. The command writes no event itself: the same INSERT made by any `skiw_app` SQL writes the same row, or is refused when `skiw.operator` is missing or malformed. `unassign` deletes, and the trigger writes `role.unassigned` from `OLD`; the last Owner assignment is refused by the command and, if two unassigners race, by the deferred trigger at the second commit (exit 1, nothing changed, no event). The user's next request sees the change (no session work).

**5.4 Role definition (operator).** Same frame (operator check → `with_agency` → roles lock → `skiw.operator`). `create <name>` inserts a non-system role (`role.created`); `rename` updates `name` only (`role.renamed`, none if unchanged); `permission set <role> <code> --scope <s>` inserts a tick — an unknown code or a scope the code does not allow fails the FK (exit 1, no event) — (`permission.set`); `permission unset` deletes it (`permission.unset`); changing a scope is `unset` + `set` in one command run, two events; `delete <role>` refuses a role with assignments, else unticks each pair then deletes the role (one `permission.unset` per pair, one `role.deleted`). On the Owner role, `delete` and `unset` are refused by the command and the database; `set` is a no-op (it already holds every pair). `accounts_org add|move|rename` takes the same lock and sets the operator; `org_unit_audit` writes `org.added`, `org.moved` (old parent from `OLD`) or `org.renamed`; the tree guard refuses a cycle or a depth past 32 (no event).

**5.5 Starting-role seed (post-migrate, Decision 5).** In the agency seed's transaction, as `skiw_migrator`: **first** check whether the agency already has a system role (a plain read; if it has, stop, issue no `ALTER TABLE`, so a routine deploy takes no ACCESS EXCLUSIVE lock on `security_event` [A: `ALTER TABLE … NO FORCE ROW LEVEL SECURITY` takes ACCESS EXCLUSIVE; review R8 P2]). Only when seeding: `NO FORCE` on `role`, `role_permission`, `security_event` → `set_config('skiw.operator', 'seed', true)` → insert Owner (`is_system`) and its 31 ticks from `SEED_DEFAULTS`, each row writing its audit event → `FORCE` back on and checked in `pg_class` → commit (deferred `role_system_complete`). An agency that already has a system role is left alone, with no lock taken.

**5.6 Enqueue (request or handler).** Inside `with_agency(A)`: refusals (loop, atomic, `agency_id` keyword, undeclared key, non-uuid) → (1a) bound = current = A → (1b) ids visible → sign → `.defer()` on the same connection. Rollback removes the job with the data.

**5.7 Worker runs an ordinary job.** Fetch (worker's async thread, autocommit) → pool thread → wrapper: MAC parse/verify/expiry (fail → `JobRefused`, no token) → ids parse → `with_agency(agency)` → re-read rows (missing → `JobRefused`) → handler; a child `enqueue_in_tx` inside joins this transaction → commit → finish. Handler raise → rollback (child gone) → library owned retry per task strategy (kept, D5 (1)).

**5.8 Periodic tick.** Procrastinate's deferrer inserts the parent with `{"timestamp": t}` → fetch → admission (Decision 18) → for each deployment agency: own transaction, `job_fanout` insert, child enqueue → parent finishes, or fails after attempting all. Re-run of the tick (admin retry inside the window) creates only missing children. Outside the window: refused, nothing written.

**5.9 Worker loses its database.** Heartbeat fails → `stop()` → no new fetch within 2 × heartbeat (20 s); shutdown waits `SKIW_WORKER_SHUTDOWN_GRACEFUL_S` (20 s) then the watchdog exits at `SKIW_WORKER_HARD_EXIT_S` (30 s) after shutdown began; Compose restarts it (`restart` policy, H1); deploy stops send SIGKILL after `stop_grace_period` (40 s). An interrupted `doing` job stays `doing` and appears in `jobs_stalled`; nothing re-queues it (release is M5).

**5.10 Retry a failed job (operator).** `jobs_retry_failed <id>` → lock row, `status='failed'` or refused → `procrastinate_retry_job_v2` → worker re-verifies the MAC (expired → refused again).
