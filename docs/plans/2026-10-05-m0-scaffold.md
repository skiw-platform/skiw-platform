**Procrastinate facts verified from the 3.10.0 source** (basis of spec v1.8 D5): `procrastinate.contrib.django` uses `DjangoConnector`, which runs every query on `django.db.connections[alias].cursor()`, so a synchronous `.defer()` inside `transaction.atomic()` on that alias runs in the caller's transaction; its `*_with_connection` methods raise `ConnectorException`, so `configure(connection=…)` is not used; `.defer_async()` goes through `sync_to_async` on another thread (not same-transaction, hence the event-loop refusal); JSON job args cannot serialise `uuid.UUID` (hence canonical strings); the worker command swaps in `get_worker_connector()` (`PsycopgConnector` from Django's DB settings, i.e. `skiw_app`).

## 7. Risks / what the reviewer should look at first

1. **[A] Same-transaction enqueue (EVT-01).** Proven only by the M0c commit/rollback/invisible tests run as `skiw_app`. **Fallback criterion (exact):** only if those tests cannot be made to pass with the Django connector — rollback leaves a job, commit loses one, or the job is visible from another connection before commit — M0c stops and switches to a `job_outbox` table written in the same transaction plus a singleton, id-idempotent relay (EVT-02 then applies; spec D5). Serialisation, grant or worker problems are fixed in place and never trigger the fallback. Re-run the tests in any PR that enables `OPTIONS["pool"]`.
2. **Grant matrix drift.** Grants are per-object, derived from 3.10.0. Every Procrastinate upgrade PR re-derives the §4.1 list and re-runs the grant audit and lifecycle test as `skiw_app` (spec D5).
3. **Builtin task.** Procrastinate registers `remove_old_jobs` itself; `skiw_app` cannot run it (no DELETE on jobs) and nothing defers it. The registry test excludes builtins by name; reviewer should confirm the worker cannot be made to run it as `skiw_app` with effect.
