**Procrastinate facts verified from the 3.10.0 source** (`tasks.py`, `connector.py`, `contrib/django/*`):
- `task.configure(connection=…).defer()` exists; docstring: supported by `SyncPsycopgConnector`, `PsycopgConnector`, `SQLAlchemyPsycopg2Connector`.
- `procrastinate.contrib.django` builds its app with **`DjangoConnector`**, whose `*_with_connection` methods are the base-class defaults that **raise `ConnectorException("… does not support external connections")`**. So spec D5 step (3) as written fails under the Django integration.
- `DjangoConnector` runs every query on `django.db.connections[alias].cursor()` — the calling thread's Django connection — so a sync `.defer()` inside `transaction.atomic` uses the same connection and transaction. The async path wraps it in `sync_to_async` (a different thread, so possibly a different connection) — hence the event-loop guard.
- The worker command swaps in `get_worker_connector()` (`PsycopgConnector` from Django's DB settings); Django connector has no LISTEN/NOTIFY.

**Not verified:** image digests (resolve at implementation and record); exact action commit SHAs; `uv audit` (exists in uv 0.11.24 but undocumented here; not used); `pnpm audit` against the current npm advisory endpoint (run once in M0d and record the result); whether `p/…` Semgrep registry rulesets download without login (if not, custom rules only, record it); TypeScript 7 / Vite 8 interplay (avoided by pinning TS 6.0.3); Django ASGI under gunicorn 26 + uvicorn-worker 0.4.0 (proved by the M0a Compose acceptance test and the M0d image job).
