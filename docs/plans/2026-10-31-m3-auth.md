- **(c) Key-version bound.** `KEY_LINE` in `app/config/env.py:22` and `infra/host/skiw_host/bootstrap_secrets.py:30` is `v([1-9][0-9]*)` [V]; `source_key.SEALED` accepts `v[1-9][0-9]{0,5}` [V `source_key.py:21`], so a 7-digit version starts but cannot verify its own seals. ### M3c — `feat/m3c-throttle-and-security-events` (CI)
- `accounts` migration: `auth_throttle(key_hmac bytea, window_start timestamptz, count int, primary key (key_hmac, window_start))`; `security_event(id uuid, at, kind, email_hmac, ip_hmac, details_json)` (§4.1). - `app/accounts/auth/throttle.py`: one statement per counter, `INSERT … ON CONFLICT DO UPDATE SET count = count + 1 RETURNING count`. Keys: HMAC-SHA-256 under `tenant_source_key`, labels `skiw-throttle-account-v1` / `-ip-v1` / `-lock-v1` over the normalised email or IP [A — the spec says "keys are HMACs" and names no key]. **Every key is derived for unknown emails too**, so limits and the soft-lock never reveal whether an account exists. - Semgrep `auth-tables-accounts-only`: `auth_throttle`, `security_event` (and later `auth_stepup`) are written only in `accounts.auth`.

### M3d — `feat/m3d-users-sessions-wrapper` (after M4-core; Q1, Q3, Q7)
- **No `django.contrib.auth` (Q7 (a)).** Installing it creates `auth_permission`, `auth_group` and their join tables [V `contrib/auth/migrations/0001_initial.py`], none in the closed global list; `AbstractBaseUser` carries a `password` column [V `contrib/auth/base_user.py:44`], which §4.1 forbids; `AuthenticationMiddleware` imports `contrib.auth.backends`, which imports `contrib.auth.models` [V `backends.py:4`, `middleware.py:10`], and D26 forbids ORM work in middleware anyway. - **Revocation marker (carry-over (b), owner Q2 = A).** Table `session_revocation(id, agency_id, user_id, session_key_hash null, revoked_at)`, append-only: `skiw_app` SELECT and INSERT only (added to the TEN-03 list). A row with `session_key_hash` revokes one session (logout, idle expiry, a rotation of an authenticated session); a row without it revokes every session of that user issued at or before `revoked_at` (AUTH-07). `authorized_action` checks it in the same `with_agency()` transaction that reads `status`: reject if a row matches the stored key, or a user-wide row has `revoked_at ≥ _skiw_auth_at` (`_skiw_auth_at` is inside the M2c MAC). Revocation = marker insert + row delete in one transaction; a failed insert fails the revoke. **Stops:** an `INSERT` as `skiw_app` that puts back a deleted (logged-out, rotated or revoked) session row, saved earlier by SQL, for the rest of its ≤ 12 h lifetime — the marker cannot be removed (no UPDATE, DELETE or TRUNCATE). **Does not stop:** a live, never-revoked session used with a stolen cookie; SQL that inserts markers or deletes session rows (logout DoS, already listed in §4.2 (b)); code execution in `web` (holds the keys); anything outside its scope inside agency A (§4.2 (a)). **Cost:** one indexed SELECT per authenticated request (`(agency_id, session_key_hash)`, `(agency_id, user_id, revoked_at)`), one INSERT per logout or revocation; ≈ 5 users, so the table stays small; v1 deletes no rows (cleanup, if ever, as `skiw_migrator`). **Rejected:** a per-user generation counter on `app_user` (SQL in agency A can UPDATE it back, and per-user only means every sign-out logs out all devices); a global table (the closed list would need a spec change).
- `accounts/auth/wrapper.py` `authorized_action(*, schema, permission)`: session (complete login, no pending state) → tenant (`with_agency(_skiw_agency)`, then `status = active` and the revocation check) → role/permission (until M4-rest: "authenticated with a second factor"; AUTH-03 is n/a until then) → input schema (UNI-03; own validator per Q3 (a)) → idempotency (no M3 route needs it; each route states why in its self-check) → handler. **Idle timeout** (M2 Q2 (a), enforced from M3): reject when `now - _skiw_seen_at ≥ SKIW_SESSION_IDLE_MIN`; `_skiw_seen_at` is refreshed at most once a minute [A] (a session write recomputes the MAC). The wrapper lives in `accounts` for M3; making it importable by other apps (independence contract) is decided when the first non-`accounts` mutating route appears (M4-rest/M5) (Risk 8).
- CSRF gate: a logged-in fixture (M2d deviation (b)); every M3 route goes through `route(…, auth="cookie")`.

## 7. Risks / what the reviewer should look at first

1. **Ownership of `guard` objects.** PostgreSQL 17: "To alter the owner, you must be able to SET ROLE to the new owning role" [V postgresql.org/docs/17/sql-alterfunction.html]. `skiw_migrator` is a member of no role and `roles.sql` aborts on any membership other than `skiw_backup` in `pg_read_all_data` [V `infra/host/db/roles.sql:34-55`]. So no migration can make a function owned by `skiw_auth_lookup` today. M4-core must choose a `postgres` socket step in `bootstrap-db` or a narrow, tested membership (a `roles.sql` change). M3e/M3g depend on it.
2. **Uniformity leaks.** Any difference between the known-wrong and unknown paths (an extra query, a skipped counter, a different header, an early return on a disabled account) is an enumeration oracle. The reviewer checks the M3e order and the structural test first; the timing band is the second line.
3. **Argon2 memory.** 64 MiB per verify; concurrent logins multiply it against the `web` memory limit in `infra/host/compose.yml` [A — limit value to read at M3b]. M3b measures peak RSS for 4 parallel verifies and records it; the IP limit bounds abuse.
4. **Revocation check on every request.** Missing it on one path (async, a new route) brings back the re-insert. The wrapper is the only path, and a registry test fails a route without it.
5. **`__Host-` cookies and RP ID on localhost** (k): if Chromium drops the cookie on `http://localhost`, e2e moves behind Caddy with `tls internal` in M3a.
6. **Interim role step.** Until M4-rest, any active user with a second factor passes the role step; there is no client data yet, so no data is exposed, but every M3 route's self-check says so.
7. **Spec D7 "Django auth"** is met by Django sessions, CSRF and signing, not `django.contrib.auth` (Q7).
8. **The wrapper's home.** Apps are independent (`pyproject.toml` independence contract), so other apps cannot import `accounts.auth.wrapper` as is; this is decided before the first non-`accounts` mutating route.
9. **Plan size.** Nine work packages (more PRs where split, §1) plus M4-core; M3d, M3e, M3g, M3i are at the limit (§1). M3g now comes last and carries the screens and e2e that were M3i's passkey parts, so it probably splits into M3g-1 (server) and M3g-2 (screens and e2e) (amended 2026-11-09).
