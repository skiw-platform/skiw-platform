### What was checked
- **The registry walk** reuses the gate's `walk()`, so `include()`d and namespaced routes are visited. A
  namespaced `ns:shell` or an unnamed route doesn't match a `PUBLIC_ROUTES` key, so it is flagged.
- **`skiw_action` survives `route()`:** `require_http_methods` uses `functools.wraps`, which copies
  `__dict__`. The "wrapped route passes through `route()`" test proves it.
- **`PUBLIC_ROUTES` reasons are sound:** `healthz`, `readyz`, `asset` and `shell` are all GET, need no
  login, and carry no tenant data beyond status. I sign off on the four entries.
- **Not walking the test URLconfs** is right: the app never serves them, and listing `csrf-probe` as
  public would weaken the list.
- **The async check** fires on an `async def` handler. `inspect.iscoroutinefunction` also unwraps
  `functools.partial`. An object with an async `__call__` would slip past it, but the handler type hint
  forbids that and nothing does it.
- **The logged-in CSRF gate:**
  - The fixture loads the shell, runs `login()` server-side, and gives the client the new session key
    and the rotated secret from `request.META["CSRF_COOKIE"]`.
  - The four refusals give the expected codes. The "before-login" case (`token-invalid`) proves the
    rotation, and the builder's no-`rotate_token()` mutant is killed.
  - The no-DB gate expects the wrapper's 401 for `action-probe`. That is correct: with no session key the
    store reads no database.

### Findings

### [P2] #1 — An unwrapped route that reuses a public route's name passes the registry
- **Category:** auth guard gap (AUTH-02, UNI-19)
- **Evidence:**
  - `unauthorized()` in `app/tests/test_route_registry.py` decides "public" by `name in PUBLIC_ROUTES`.
    Django allows several patterns to share one name, and nothing in `route()` or the gates rejects that.
  - My probe added `route("admin-ish", <unwrapped view>, name="healthz", methods=("POST",),
    auth="cookie")`. The registry returned no problem.
  - The CSRF gate doesn't catch it either: it finds the `healthz` fixture and only tests CSRF.
- **Failure scenario:** a later PR copies a `route(...)` line and keeps the name, or picks a name that's
  already public. The new route then serves without a login, and `make test` stays green. That is the
  exact case AUTH-02's registry is meant to stop.
- **Required correction:**
  - Fail on a route name that appears more than once in the walk, with a test. Alternatively, key
    `PUBLIC_ROUTES` on the name and the pattern together.
  - Add the duplicate-name case to the registry tests.
- **Owner:** builder · **Disposition:** fix here (small) · **Status:** open

### Notes (no action)
- **A hand-set `skiw_action` passes the registry.** Doing this on purpose is not the threat the registry
  addresses, and review covers it. If you want it closed, `authorized_action` could put each view it
  makes in a module-level `WeakSet`, and the registry would check membership, not the attribute.
- **The live "reaches the handler" test also accepts 400 and 422.** `action-probe` returns 200 `done`, so
  the test could assert that for wrapped routes. As it stands, a wrapper that refused every body with
  400 would still pass it. Other wrapper tests would catch that, so I'm not asking for a change.
