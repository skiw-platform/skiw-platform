### [P2] The first-host runbook starts the database before generating its required HBA file
- Category: defect
- Rule: UNI-16; reviewer §7 executable operator runbooks.
- Evidence: `docs/runbooks/host-rebuild.md:122–127` says to run after `docker compose up -d db`, then shows prepare followed directly by apply. Lines 131 and 146–149 instead require prepare before the first up. This PR makes `/etc/skiw/db/pg_hba.conf` a required Compose config (`infra/host/compose.yml:112–114, 167–168`), generated only by prepare (`infra/host/skiw_host/bootstrap_db.py:86–102`).
- Failure scenario: on a fresh/rebuilt host, an operator follows the opening prerequisite and starts db before prepare. Its required HBA source file does not exist, so the container cannot start. I reproduced this with the new live fixture in an isolated Compose project, omitting only the generated HBA file: startup refused because the bind source pg_hba.conf did not exist. The disposable project was cleaned up.
- Why it matters: the recovery runbook gives contradictory ordering for a new mandatory startup dependency. The correct implementation and authentication matrix work when invoked in the correct order. Severity is P2 rather than the usual failed-guardrail P1 because this is an isolated documentation/order defect, later bullets already state the right dependency, and it does not weaken authentication or disclose data.
- Required correction: give one ordered fresh-host sequence: bootstrap-secrets init/restore → bootstrap-db prepare with the environment file → start/wait for db using that same Compose/environment configuration → bootstrap-db apply. Remove the conflicting opening prerequisite and include the db startup between prepare and apply in the command block. Retain the separate subnet-change instructions.
- Owner: Builder.
- Verification: read the complete sequence top to bottom against the generated-file dependency; confirm prepare precedes the first db start and apply follows a ready db. The existing live authentication tests already verify the successful prepared-file path.
- Disposition: before merge.
- Status: open.
