- Category: objective defect / security and spec mismatch; incomplete membership validation within the Round 1 role-set correction.

- Evidence: `infra/host/skiw_host/hardening.py:449–452` ignores every membership whose member and group are both predefined roles, rather than only PostgreSQL's actual baseline grants. Separately, ROLES_QUERY at lines 47–48 and the Members model/parser keep only the member/group names, omitting the membership's admin/inherit/set options. - Failure scenarios, independently reproduced on native PostgreSQL 17.11:
  1. `GRANT pg_write_all_data TO pg_read_all_data;` is accepted as a predefined-to-predefined grant. skiw_backup already belongs to pg_read_all_data, so this adds indirect write privileges. The required backup read access was removed without detection.
- Why it matters: recognizing a role as PostgreSQL-predefined does not make new grants involving it legitimate. Likewise, a membership pair does not establish its effective privileges. The gate can certify either a widened backup identity or one unable to read the data it must back up. The configured read-only default is not a substitute for verifying the required privilege graph.
- Primary-source corroboration: [PostgreSQL predefined roles](https://www.postgresql.org/docs/17/predefined-roles.html) distinguishes read-all-data and write-all-data and identifies pg_monitor's own grants; [role membership](https://www.postgresql.org/docs/17/role-membership.html) explains indirect inheritance and SET; [pg_auth_members](https://www.postgresql.org/docs/17/catalog-pg-auth-members.html) exposes the admin, inherit and set flags that the current query omits.
- Required correction: compare memberships with an explicit policy: the grants in roles.sql plus the actual pinned PostgreSQL baseline grants, with their required options. Remove the blanket predefined-to-predefined exception. Query and validate admin_option, inherit_option and set_option so privilege-changing option drift cannot pass. Keep comparisons and diagnostics value-free, and update the runbook/decisions claims to match the enforced policy.
- Owner: Builder.
- Verification: native baseline, including the three pg_monitor grants, passes. The extra predefined-role grant and the option change above each produce FAIL role-set / exit 1.
