### Findings

### [P1] #1 The invitation token stays in the address bar when the visitor is not signed out
- Category: security
- Rule: AUTH-08 (single-use enrolment link, handled as a secret); PR 149 R1 P3 #3; DECISIONS "M3i-2" ("reads the `#token` once, removes it from the address bar")
- Evidence: `takeToken()` is called only from `SignedOut` in `App.tsx`, so the fragment is read and removed only when `/api/auth/session` answers `signed_out`. **Reproduced** with a scratch vitest probe (not added to the repo): open `/enrol#tok-999` with the session answering `signed_in`, `second_factor` or `enrol_factor`. The page shows Today, the code step or the setup step, and `window.location.hash` is still `#tok-999` in all three (3 of 3 probes failed on that assertion).
- Failure scenario: the owner creates an invite on the office PC where they are signed in and opens the printed link to check it, or a new adviser opens their link on a shared machine where a colleague is signed in. The token now sits in the address bar and in browser history for that tab, readable by anyone who uses the machine next. While the link is valid (`SKIW_ENROL_LINK_MIN`, 30 minutes) and still unused, they can open it, set the password and enrol their own authenticator. That is a takeover of a staff account before its owner ever signs in. Also, if that signed-in person later signs out on that tab, `SignedOut` reads the leftover token and shows the invitation screen for someone else's invite.
- Required correction: take the fragment out of the address bar on page start, whatever the session state, before or alongside the first session request. For example, call `takeToken()` once at module load or in `App`'s first effect, not in `SignedOut`'s render. Then decide what a non-signed-out visitor at `/enrol` sees. The smallest safe choice: drop the token (`forgetToken()`) and `leaveEnrol()` when the state is not `signed_out`, so a later sign-out does not show someone else's invitation. Add vitest cases for `/enrol#token` with `signed_in`, `second_factor` and `enrol_factor`: the hash is gone, and after a sign-out the invitation screen does not appear.
