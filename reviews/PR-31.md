### [P2] branch -d acceptance does not prove the branch is fully merged into the default branch
- Category: objective safety-proof defect
- Rule: proposed builder cleanup condition 2; START merged proof / clean-only cleanup intent
- Evidence: agents/roles/builder.md:115–118 permits cleanup when local tip matches the final PR head OR git branch -d accepts it. [Git branch documentation](https://git-scm.com/docs/git-branch) specifies -d checks the configured upstream, using HEAD only when no upstream exists.
- Failure scenario: PR merged at A; its local branch/worktree later contains pushed B and tracks origin/feature also at B. The old PR is merged, tip differs from its final head, worktree is clean and has no unpushed commits. branch -d can accept because B equals its upstream, even though B never landed on the default branch. The rule then automatically removes an active feature worktree/local branch instead of leaving the post-PR work alone.
- Why: isolated P2, not a claim of lost committed data: remote branches are expressly retained, so B remains remotely recoverable. But the rule's fallback does not establish the promised fully-merged condition and authorizes cleanup beyond the merged PR's reviewed work.
- Required correction: keep exact-final-head equality as the squash-merge path. For a differing tip require an explicit read-only ancestry check against the freshly fetched project default branch (for example merge-base --is-ancestor <local tip> origin/<default>), or remove that fallback and require equality only. Do not treat git branch -d itself as merge evidence. Use it only as the later deletion operation when appropriate. Evaluate proof before worktree removal; normal -d cannot be used as a preflight oracle while the branch is checked out in that linked worktree.
- Owner: owner/master-kit maintainer updates the canonical rule; Builder recopies the owner-approved result. Reviewer never edits either copy.
- Verification: reasoning/check cases cover exact merged squash head, differing tip already on default, pushed post-PR tip only on feature upstream, dirty/unpushed worktree and default/main-checkout exclusions. The third case must preserve branch and worktree. No destructive reproduction required.
