- Category: operational documentation defect
- Rule: UNI-16; Reviewer §7 executable runbook; spec H2 password-protected sudo and H4 plaintext streaming
- Evidence: docs/runbooks/host-rebuild.md:58–59 pipes age decryption directly to ssh operator@host sudo bootstrap-secrets restore. Spec:709 plans an operator account with password-protected sudo; no narrow passwordless restore rule, askpass/elevation mechanism or preflight is documented for this command.

Restore never starts. Its stdin is already the plaintext bundle, so sudo -S would consume recovery input as a password; simply adding a terminal is not an established safe secret-streaming design.

Isolated P2 rather than a broad runbook-control failure: the restore runbook is updated in this PR, the code/tests work, and this elevation failure stops before any secret-store mutation. No actual key disclosure or host failure was reproduced.
- Required correction: state and stage the narrow noninteractive elevation prerequisite explicitly, with its host-hardening owner/follow-up, and make the example fail closed when it is absent (for example sudo -n in the non-terminal stream once an approved mechanism exists). Document an authorization preflight before decrypting. Do not suggest global passwordless sudo, SSH root login, sending a sudo password into the bundle stream, or an unvalidated echoing tty. It is acceptable for the actual elevation provisioning/live proof to remain M1f/M1k if the command is clearly conditional and cannot be mistaken for ready-to-run today.
