### What was checked
- **The AUTH-01 order** in `wrapper.py` matches the plan:
  1. session;
  2. tenant, in one `with_agency(<session's _skiw_agency>)`: idle, then `status = 'active'` and
     `revoked()`;
  3. role (the interim "second factor present", owner Q9 (a));
  4. input;
  5. idempotency (n/a);
  6. the handler, in the same transaction.
  - The order test runs four cases, and the builder's "role after input" mutant is killed.
- **Idle:**
  - The test is `now − _skiw_seen_at ≥ SKIW_SESSION_IDLE_MIN`.
  - Expiry writes a key marker, then flushes, in one transaction, so a failed marker leaves the session
    alive (tested).
  - The saved row, put back with a fresh idle clock, is refused as revoked.
  - Refreshing `_skiw_seen_at` at most once a minute means a session can expire up to 59 s early, never
    late.
- **The refresh can't resurrect a row.** Django's `db.SessionStore.save()` on an existing key uses
  `force_update`, so a deleted row raises `UpdateError`, which the middleware turns into a 400. The
  handler's transaction has already committed by then; that is an acceptable edge.
- **Absolute 12 h:** activity every 29 minutes never moves the deadline, and the session is refused at it.
  This proves that only `login()` renews the deadline.
- **Status and revocation:**
  - Both are checked inside the session's agency, so RLS scopes `app_user` and the markers to that
    agency.
  - Both refusals flush and give the same `signed-out` code, so the response doesn't tell disabled apart
    from revoked.
  - The user-wide marker test pins the tie to the marker's own `revoked_at`, which removes clock skew
    from the test. Put-back copies are refused too.
  - A not-`active` user gets no marker. This is recorded for M4-rest's disable flow, which must call
    `revoke_user()`. That is correct: status is checked on every request.
- **TEN-11:**
  - `Signed` and the binding come only from the MAC-verified session.
  - A forged agency B in the query, the body and three headers is ignored. The handler's
    `guard.current_agency()` is the session's agency.
  - Variant (i), a re-signed `_skiw_agency`, gives 401 and a logout.
- **Input (UNI-03):**
  - Safe methods give the schema `{}`.
  - Other methods need `application/json` (Django's `content_type` strips the parameters, so
    `; charset=utf-8` is accepted) and a JSON object.
  - Six bad bodies each give 400 `invalid`, with no detail.
  - `DATA_UPLOAD_MAX_MEMORY_SIZE` still caps `request.body`.
- **Removing the two `_signed()` checks is sound:**
  - A row that fails the MAC loads empty, so `_skiw_*` can't appear without a key.
  - Only `login()` writes those keys, with UTC-aware times.
  - A missing or bad value is still treated as no login (`KeyError`/`TypeError`/`ValueError`), never a
    500.
- **The test view** lives only in `accounts/tests/urls.py` and records what it saw instead of echoing it.
- **Size:** 453 lines of code and tests, plus 49 lines of DECISIONS. That is at the ≈ 450 rule, and
  disclosed; I accept it.

### Notes (no action)
- **`auth_at` against `seen_at` in `revoked()` can't be told apart by any reachable sequence.**
  - A user-wide marker has to commit before a request can refresh `seen_at` past `revoked_at`.
  - The first request after the marker reads the old `seen_at`, which is earlier, and is refused and
    flushed before any refresh.
  - A concurrent request takes `now` before the marker, so its refresh is also earlier than
    `revoked_at`.
  - The code uses `auth_at`, which is the right field. I'm not asking for a test.
- **The refresh only happens after the role and input checks pass.** A 403 or 400 doesn't extend the
  idle window. That is the stricter choice, and the code does it, but no test pins the ordering. If
  M4-rest moves the role step, it should keep the refresh after it.
