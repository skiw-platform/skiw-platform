### Findings

### [P2] A failed delivery of the monthly `check-hardening` alert waits a month
- **Category:** material risk (resilience of an alert path).
- **Rule:** spec §8.4 H7 ("the monthly `check-hardening`" with alerts), H2; plan §3 M1j.
- **Evidence:** `health.py` `step()`: a bad check counts as announced only after delivery; it is
  retried "next run". For `check-hardening` the next run is the monthly
  `skiw-hardening.timer` (`OnCalendar=monthly`). The 5-minute `skiw-health` run does not read
  `hardening.state` or the failed state of `skiw-hardening.service`.
- **Failure scenario:** after M1j-2, the channel is down for a few minutes during the monthly run
  (mail provider outage, Telegram timeout). `check-hardening` found `secret-store` failing. The
  alert is only in the journal, and it is tried again about 30 days later.
- **Why it matters:** H2 failures are security drift (firewall, sshd, secrets, roles). The monthly
  run is the only thing that reports them.
- **Required correction:** a due, undelivered `check-hardening` message is retried on the next
  5-minute run, for example: `skiw-health` also reads `hardening.state` (or
  `systemctl is-failed skiw-hardening.service`) and re-sends the owed message. Add a test.
- **Owner:** Builder.
- **Verification:** a test where the hardening alert fails once and the next 5-minute run delivers it.
- **Disposition:** deferred to M1j-2 (the first PR that can deliver anything off the host; today
  every message is journal-only, so the gap cannot occur yet).
- **Status:** open.

### [P2] `security-updates` cannot see updates when the package lists are stale
- **Category:** material risk.
- **Rule:** spec §8.4 H7 "pending security updates"; the check's own docstring ("pending this
  long means it is not working").
- **Evidence:** `health.py` `updates()` runs `apt-get --simulate dist-upgrade` against the local
  package lists. If `apt-get update` stops working (the `apt-daily` timer disabled, the mirror or
  DNS unreachable), the lists never show a new security version, so the count stays 0 and the
  check is `ok` forever. Nothing checks the age of the lists.
- **Failure scenario:** the mirror is unreachable for weeks. No security update is installed, and
  `skiw-health` reports "0 security updates pending" every 5 minutes.
- **Why it matters:** this check is the only alert that unattended security patching has stopped,
  on an internet-facing host.
- **Required correction:** the check is also bad when the lists are older than a named threshold
  (for example `/var/lib/apt/periodic/update-success-stamp`, or the newest file in
  `/var/lib/apt/lists`, older than 48 h), with the age in the value. Add a test.
- **Owner:** Builder.
- **Verification:** a test with old lists and no pending updates gives `bad`.
- **Disposition:** deferred to M1j-2 (before any host runs it; real hosts come in M1k).
- **Status:** open.

### [P3] A check that fails on every other run never alerts
- **Evidence:** `step()`: a check with a 240 s grace must be bad on two runs in a row. One `ok`
  run resets `bad_since`. The runbook says so ("A check that flips between runs sends nothing new").
- **Effect:** `/readyz` failing 50 % of the time (for example an intermittent database error) is
  never alerted. Container restarts are still alerted as events.
- **Suggested correction:** count bad runs in a window (for example 3 of the last 6), or record it
  in DECISIONS as accepted.
- **Owner:** Builder / owner. **Status:** open (non-blocking).

### [P3] "Journal first" is not tested when a transport exists
- **Evidence:** reviewer mutant A8: moving the journal line in `alert.deliver` inside
  `if transport is None:` (so a message sent through a transport is never journaled) left all 713
  host tests green. Only the no-channel path is tested.
- **Effect:** none today (no transport). In M1j-2 a slip would send alerts off the host with no
  journal record.
- **Suggested correction:** in M1j-2, a fake-transport test asserts the journal line comes before
  `send`, on success and on failure.
- **Owner:** Builder. **Status:** open (non-blocking).
