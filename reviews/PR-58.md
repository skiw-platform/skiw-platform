### Findings

### [P3] The bootstrap mains' switch to `say()` has no test
- **Evidence:** reviewer mutations on a scratch copy. Each of these left all tests green:
  - a raw `print(..., file=sys.stderr)` back in place of `say()` on the refusal path of
    `bootstrap_secrets.main` (`bootstrap_secrets.py:253`);
  - the same in `bootstrap_db.main` (`bootstrap_db.py:181`);
  - `say()` catching `OSError` only, without `ValueError` (`bootstrap_secrets.py:188`);
  - `record()` without the `finally`, so the stderr copy is not printed when the log write fails.
  The `skiw-deploy` paths are tested (closed-channel tests, both order mutations killed).
- **Effect:** small. If one of those prints comes back and the owner's SSH session drops, a
  refusal exits 1 (or 120) instead of 2. These paths write no durable record, so nothing is lost.
- **Suggested correction:** one closed-stderr test for a `bootstrap-secrets` and a `bootstrap-db`
  refusal (exit 2), and one for a closed stream (`ValueError`).
- **Owner:** Builder. **Status:** open (non-blocking).

### [P3] The build check imports a fixed module list, not `predeploy.py`
- **Evidence:** `Dockerfile:28` checks `import hashlib, ssl, subprocess, tempfile`. In the image
  I built from this head, 5 standard-library C modules cannot load, because their libraries are
  not in the postgres base: `_bz2`, `_sqlite3`, `_curses_panel`, `_tkinter`, `nis`. Today
  `predeploy.py` loads fine (reviewer probe below).
- **Effect:** if `predeploy.py` later imports `bz2` or `sqlite3`, the image still builds and scans
  clean. It fails only at the first deploy, at the dump step, before `migrate`. That fails closed.
- **Suggested correction:** make the build check load `predeploy.py` itself, for example by
  importing it as a module without running `main`.
- **Owner:** Builder. **Status:** open (non-blocking).
