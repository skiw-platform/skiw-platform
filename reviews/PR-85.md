### Findings

### [P2] `tenancy-no-session-setting` misses two literal `false` forms, and both leave a session-level setting
- Category: security control (lint boundary)
- Rule: TEN-09 (hard; this rule is its lint guard, spec line 380 "Plain `SET`/`set_config(…, false)` stay banned by Semgrep"); UNI-04
- Evidence: `semgrep/tenancy-boundaries.yml:63`, regex `set_config\s*\([^)]*,\s*(false|'f'|'false'|0)\s*\)`. `[^)]*` cannot cross the first `)`. The value list has only four spellings. In a scratch git repo with the PR's rule file, `uvx semgrep==1.179.0 --config semgrep/ --metrics=off --error app` on `app/tenancy/binding.py` flagged only line 5 of these:
  - line 2: `SELECT set_config('app.tenant_token', guard.mint_token(%s), false)` (a nested call in the value) — **not flagged**
  - line 3: `SELECT set_config('app.tenant_token', %s, %s)` with `False` as a parameter — not flagged
  - line 4: `SELECT set_config('app.tenant_token', %s, 'off')` — **not flagged**
  - line 5: `SELECT set_config('app.tenant_token', %s, false)` — flagged

  PostgreSQL 17 proof (throwaway container): `SELECT set_config('app.x', 'v', 'off')` and then `current_setting('app.x', true)` in the next statement gives `v`. `BEGIN; SELECT set_config('app.y', format('%s','w'), false); COMMIT;` and then `current_setting('app.y', true)` gives `w`. So both missed forms make a session-level setting. PostgreSQL also accepts `'no'`, `'n'`, `'0'` and the prefixes `'of'`, `'fa'`, `'fal'` as false (PG docs, boolean type; I did not run these).
- Failure scenario: M4c-4b writes `with_agency()` in `tenancy/binding.py`, the one file where the token rule is off. A wrong last argument with a nested value call (`set_config('app.tenant_token', guard.…(…), false)`) passes `make lint`. The minted token then stays on the pooled connection after `COMMIT`. The next request on that connection that runs outside `with_agency()` reads the old agency.
- Why it matters: PR 80 P2 was the same class of regex escape in `auth-tables-accounts-only`, and I graded it P2. The rule text says "banned everywhere", and the fixture cannot show the gap, because every `ruleid` line has a flat second argument. Only P2: no code calls `set_config` today, and the plan's `with_agency()` form (plan line 274, `set_config('app.tenant_token', %s, true)`) is caught correctly.
- Required correction: flag every `set_config(` in a SQL string whose last argument is not the literal `true` (case-insensitive). One way: match `set_config\s*\(` and add a `pattern-not` / `metavariable-regex` exclusion for `,\s*true\s*\)` on the same call. Add fixture `# ruleid:` lines for a nested-call value with `false`, for `'off'`, `'no'` and `'0'`, and for a `%s` last argument. Keep `# ok:` lines for `…, true)` with a nested value.
- Owner: builder
- Verification: the review re-runs the four `binding.py` lines above, plus the new fixture lines.
- Disposition (P2): deferred to M4c-4b (plan row 6 carries the "Semgrep TEN-09 rules" and adds `binding.py`). The builder may fold it into round 2 of this PR instead, because the file is here.
- Status: open
