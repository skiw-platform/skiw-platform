### Findings

### [P2] `owner_role` leaves the session as the owner role when a Python error is caught inside a transaction
- Category: material risk (TEN-02 (hard) area; the helper's documented contract is false)
- Rule: TEN-02; plan §3 M4c-3 "Helper"; `app/tenancy/ddl.py:28-40`
- Evidence: `owner_role` is `SET LOCAL ROLE …; yield; RESET ROLE` with no `try/finally`, and its docstring says "On an error the block's transaction rolls back, which undoes the `SET LOCAL` too". I ran a probe against a disposable DB (migrator connection, one transaction): `with owner_role(cur, 'skiw_tenant_guard'): raise ValueError` caught by the caller. Afterwards `session_user, current_user` = `('skiw_migrator', 'skiw_tenant_guard')`, and `SELECT count(*) FROM guard.tenant_mac_key` succeeds. A Python exception (not a DB error) leaves the transaction healthy and the role switched. Only a rollback undoes it, and nothing in the helper forces one.
- Failure scenario: a later caller (M4c-4a+, or a test helper) catches an exception from inside the block, for example a `CommandError` like those `keys.py` raises at `:96`, and keeps using the transaction. Every later statement then runs as the key-table owner. This is the very standing access the "no migrator grant" design (TEN-02, plan §9 item 2) exists to prevent.
- Why it matters: per `ddl.py:11-13` this helper and `as_owner` are "the only places the migrator issues `SET ROLE`". The two current callers are safe, because `keys.py` lets the error leave `transaction.atomic` and the test helpers exit the psycopg connection context. But that safety lives in the callers, not in the helper.
- Required correction: in `owner_role`, `yield` inside `try/finally`. In the `finally`, send `RESET ROLE` when the connection's transaction status is not in error (`cursor.connection.info.transaction_status != pq.TransactionStatus.INERROR`). When it is in error, leave it, since only a rollback can follow. Fix the docstring to match, and add a live test: a Python exception raised and caught inside the block leaves `current_user = skiw_migrator`, and a plain SELECT on the key table is then denied.
- Owner: builder
- Verification: the new live test, plus re-running the probe above.
- Disposition: before merge (one helper, ~5 lines; it is the TEN-02 boundary this PR introduces)
- Status: open
