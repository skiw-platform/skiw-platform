### [P3] `as_owner` in a non-atomic migration makes the migrator the owner, with only a warning
- Category: security control (object ownership)
- Rule: TEN-01, TEN-02 (spec D4: guard objects are owned by the NOLOGIN roles)
- Evidence: `app/tenancy/ddl.py`. `SET LOCAL ROLE` does nothing outside a transaction. The builder disclosed this under "Not proven". I proved it with the PR's own `as_owner("skiw_tenant_guard", ["CREATE TABLE guard.probe_na (x int)"], …)` on the review database, as the real migrator login:
  1. In a transaction: the owner is `skiw_tenant_guard`.
  2. In autocommit (what a migration with `atomic = False` does): the owner is `skiw_migrator`. The only signal is the notice `SET LOCAL can only be used in transaction blocks`.
  3. In autocommit, with one extra statement after `SET LOCAL ROLE` — `DO $$BEGIN IF current_user <> 'skiw_tenant_guard' THEN RAISE EXCEPTION '…'; END IF; END$$` — the run stops with `RaiseException`, and no table is made.
  4. In a transaction, with the same extra statement: the owner is `skiw_tenant_guard`, as before.
  
  In case 3 the earlier `GRANT CREATE ON SCHEMA guard` had already committed, so it stayed. The run still fails loudly.
- Failure scenario: M3e or M3g adds a lookup function through `as_owner` in an `accounts` migration marked `atomic = False`, for example next to a concurrent index. The function is created owned by `skiw_migrator`, not `skiw_auth_lookup`. Only an owner test catches it, and M3e or M3g may not have one for every function.
- Required correction (two ways):
  - **(a) My pick:** add the `DO` check on `current_user` as the statement right after `SET LOCAL ROLE`, in both forward and reverse. It stops every caller at the point of harm, including callers in `accounts`. Confirm that `lintmigrations` accepts the `DO` statement, and extend `test_forward_and_reverse_run_as_the_owner_and_hand_create_back`.
  - (b) A test with no database: every migration that calls `as_owner` has `atomic = True`.
- Owner: builder
- Disposition: deferred to M4c-2b, the first PR to create definer functions through the helper.
- Verification: the M4c-2b review re-runs the autocommit probe.
- Status: open
