### Findings

#### [P1] Recognizable role-name reads and filters escape the lint rule

- **Category:** guardrail mismatch.
- **Rule:** M4-rest Decision 36, §7 and UNI-04. Limit C allows incomplete coverage where the role receiver cannot be recognized. The failing examples have an explicit `Role` queryset.
- **Evidence:** `semgrep/no-role-name-branching.yml:61` matches a result assigned from a `Role` query. Its exclusion at line 65 covers the entire statement sequence with a reassignment. With Semgrep 1.179.0, the read in `r = Role.objects.get(...); label = r.name` was detected when there was no later assignment and escaped detection when a later statement assigned an org unit to `r`. The fixture at `semgrep/no-role-name-branching.py:120` tests the allowed read *after* reassignment. The queryset filter pattern at `semgrep/no-role-name-branching.yml:93` also missed `Role.objects.filter(Q(name=name))` in the independent probe, while the supplied direct-keyword fixture is detected.
- **Failure scenario:** A future authorization branch uses a name read from a known role before reusing the local variable, or filters the role queryset through a conventional `Q` predicate. The approved lint gate passes the read or filter despite the rule and PR explicitly claiming coverage of these identifiable role query cases.
- **Impact:** The primary deliverable misses recognizable authorization inputs. PR 190 adds lint only. The cases were reproduced as static fixture scans, with no runtime access change.
- **Required correction:** Keep reads before reassignment in scope and allow the read after a known non-role reassignment. Cover a direct `Q` role-name lookup on a `Role` queryset. Add positive and negative fixtures that establish those boundaries.
- **Owner:** builder.
- **Verification:** Rerun the pinned Semgrep fixture suite. Verify a role read before reassignment and a direct `Q` role-name filter are flagged, while a read after non-role reassignment remains allowed.
- **Status:** open.

- **Category:** defect.
- **Rule:** M4-rest Decision 36, role-name lint scope.
- **Evidence:** `semgrep/no-role-name-branching.yml:48` matches `getattr($ROLE, "name", ...)` without constraining the receiver. The independent Semgrep 1.179.0 probe flagged `getattr(unit, "name", None)` even when `unit` was explicitly annotated `OrgUnit`. The fixture permits the analogous direct read `unit.name` at `semgrep/no-role-name-branching.py:112`.

- **Impact:** A future legitimate display-name read would require code churn or suppression. There is no affected caller in the current tree.
- **Required correction:** Constrain reflective name reads to recognizable role receivers. Keep `getattr(role, "name", ...)` flagged and add an explicit non-role negative fixture.
