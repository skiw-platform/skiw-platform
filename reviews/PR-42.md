### Findings

### [P1] The installer treats a matching file with the wrong owner as compliant
- Category: defect
- Rule: spec §8.4 H2/H4 host privilege boundary; PR's root-owned installation contract / UNI-08 self-check evidence.
- Evidence: `infra/host/skiw_host/apply.py:115–118` checks only target contents and mode before skipping. The root:root chown at line 123 is reached only if that check fails. `plan()` installs root-executed programs and imported Python modules, including `/usr/local/lib/skiw/skiw_host/escrow.py`, plus the fixed environment file used by the passwordless restore rule. Existing idempotence/content-drift tests do not exercise ownership-only drift.
- Failure scenario: a file already has the correct contents and 0644 mode but is owned by an unprivileged account. apply reports success and leaves the file writable by that owner. I reproduced this first with an isolated local install fixture (uid 501/gid 20, zero chown calls), then with the actual root-run apply inside Ubuntu 24.04: first install succeeded, I changed only escrow.py's owner to uid/gid 1000, and the next apply printed `0 files changed` while its uid remained 1000.
- Why it matters: the non-root owner can subsequently alter a module imported by the root bootstrap-secrets process, turning the narrow restore sudo authorization into arbitrary root execution. This is a privilege-boundary weakness, not a cosmetic ownership difference. Successful file installation must establish the root ownership it promises before the later services/host-check slices rely on it.
- Required correction: include uid and gid in the compliance check and repair ownership-only drift, or refuse explicitly rather than report success. Only treat an expected, trusted file as unchanged; avoid accepting links to untrusted targets. Keep truly compliant files untouched and keep the installed modes fixed. Add tests for ownership-only drift on a root-executed module/program and for a genuinely compliant second run.
- Owner: Builder.
- Verification: seed matching bytes/mode with non-root uid or non-root gid, run the installer as root against a disposable root, and prove root:root ownership is restored (or installation fails closed). A subsequent compliant run must be a no-op. Retain the existing successful config-parser and sudo restrictions.
- Status: open.
