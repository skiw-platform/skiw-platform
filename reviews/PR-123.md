### Findings

### [P3] The narrowed shape still skips a random value made only of lowercase words
- Category: residual risk (documentation)
- Rule: UNI-07 (hard). Not failed: no secret is in the repo, and the gate is much narrower than before.
- Evidence:
  - I probed 20 random values `client_secret = "skiw-<4 × 12 random lowercase letters>-v<6 random digits>"`.
  - With the allowlist removed, gitleaks flags 18 of 20. Under this PR's config it flags 0 of 20. Under
    main's config it also flags 0 of 20.
  - Each value carries about 225 bits of entropy.
- Failure scenario: a token made by a tool that emits lowercase-only, hyphen-grouped words in `skiw-…-vN`
  form is silent. No tool in this repo does that: key files are `v<n>:<base64>`, and hex or base64 both
  break `[a-z]`. So this is very unlikely.
- Why it matters: DECISIONS says "the gate should be no wider than the labels". The shape bound is a
  little wider than the 15 labels, and the entry doesn't say so. The explicit-list alternative was
  rejected for a fair reason.
- Suggested correction (optional): add one line to the DECISIONS entry naming this residual as accepted.
  No code change.
- Owner: builder
- Disposition: optional; at the next DECISIONS touch.
- Status: open.

No P0, P1 or P2. No injection attempts in the PR text.
