#### [P2] Unhashable runtime line metadata raises instead of returning 403

- **Category:** Spec mismatch.
- **Rule:** M4-rest Decision 26 and §7's runtime metadata case.
- **Evidence:** `app/accounts/auth/wrapper.py:129` hashes `(g.line, line)` for lookup in `LINE_MATCHES`. The tampering test at `app/accounts/tests/test_wrapper_roles_live.py:212` covers invalid strings and `None`. It lacks an unhashable value. Decision 26 calls for `403 forbidden` when a runtime line falls outside the match table.
- **Failure scenario:** An independent wrapper probe changed the line closure cell of a test action after registration, with a valid grant available. `"Insurance"` and `None` returned `403 forbidden`. A list and a dictionary raised `TypeError`, which would surface as a 500 through Django.
- **Impact:** Isolated to invalid server-side metadata after registration, and the handler is unreachable in this case. Normal registration rejects these inputs. The response still misses the specified fail-closed contract.
- **Required correction:** Validate the runtime action line before hashing it. Extend the existing tampering test with an unhashable line that returns `403 forbidden` and retains the valid-line control.
- **Owner:** Builder.
- **Verification:** Recheck the exact 403 response and full wrapper line matrix on the new head.
